Integration Specification

Shopify → Salesforce Product REST API

How the Shree Hari website sends Shopify product records into Salesforce. Uses the same External Client App and the same access token as the Lead and Customer APIs; only the URL and the payload differ. Prepared by Halsa Global for the Shree Hari Jewellers website team.

ProtocolREST / JSON
AuthSame as Lead API · OAuth 2.0
PayloadShopify product object
EnvironmentUAT Sandbox

01Overview

Integration pattern: the website POSTs one Shopify product as JSON, in the shape of the Shopify Liquid product object. Salesforce stores it as one Staging Product record, with one Staging Product Variant record under it for each entry of variants, and returns the product record’s Id and number. Property names are the Shopify names, unchanged.

Every call creates a new Staging Product record, so Salesforce keeps a full history of what was sent. Records are processed inside Salesforce afterwards and need nothing further from the website.

Whatever you send is stored. All 44 properties of the Shopify product object and all 39 of the variant object are stored, and any other key is kept in Additional Properties.

03Conventions

ConventionDetail
Content-Typeapplication/json
Character setUTF-8
Property namesExactly the Shopify Liquid product property names, in snake_case — price_min, variants_count, gift_card?. Names ending in ? are also accepted without it (gift_card). Names are case-sensitive: Title is not title and would be kept in Additional Properties
Payload shapeOne product per request, as one JSON object with the properties at the top level, exactly as in the samples in section 06. A body of the form {"product": {…}} is also accepted. Arrays of products are rejected
RequiredOnly id
Empty valuesnull is accepted and leaves the field blank. A property that is left out also leaves its field blank
NumbersJSON numbers, unformatted — 12500000. Numeric text such as "12500000" is also accepted; "1,25,000" and "₹1,25,000" are rejected
MoneyThe six price properties are in the currency’s subunit, as Shopify Liquid outputs them (paise for INR), and are stored as sent
BooleansJSON true / false. The text "true" / "false" is also accepted (any letter case); anything else, such as "yes" or 1, is rejected. A true/false property that is left out is stored as false
Timestampscreated_at and published_at must carry a time zone. Accepted: "2026-10-05 11:20:45 +0530" (as Shopify Liquid outputs it), "2026-10-05T11:20:45+05:30", "2026-10-05T05:50:45Z". A value without a time zone is rejected
Objects and arraysStored as JSON text, unchanged, whatever their content
Other propertiesAny property not listed in section 04 is not rejected: it is kept on the record in Additional Properties (up to 131,072 characters of JSON for all such properties together), so nothing sent is lost
Fixed value listsNone at product level. The Shopify product object defines no property with a fixed set of values
Repeats and retriesEach successful call creates a new record, including a retry of a call that already succeeded. Retry only on 401 (after re-authenticating) and 500

05The 22 large properties — what to send

Twenty-two of the 44 properties hold an object, a list or long text. The table says what to send for each one.

  • ALL — send the property complete, exactly as Shopify gives it.
  • ID / NAME ONLY — send only the ID or the name.
  • LEAVE OUT — do not send the property.

This is based our understanding of the Shopify documentation. Nothing here is enforced: whatever you send is stored as sent. If a property we mark ID / NAME ONLY or LEAVE OUT holds information you need kept, send it complete.

#PropertyLabelWhat to sendReason
1variantsALLEvery variant, complete.SKU, price, stock, weight and options of each variant.
2imagesALLEvery image, complete.The product’s pictures.
3mediaALLEvery media item, complete.Pictures, videos and 3D models.
4options_with_valuesALLEvery option with its values, complete.The choices a shopper has, such as purity and length.
5categoryALLThe complete object.The product’s category.
6metafieldsALLEvery product metafield: namespace, key, type and value.Jewellery details such as purity, weights, stones and making charges.

Size limit. Each property can hold the length shown in section 04; a longer value is rejected with VALUE_TOO_LONG and the product is not stored. Each Product variant is stored as its own record, so the number of variants is not limited by this.

StatusMeaning

07Error responses

Every error raised by the endpoint uses the same JSON shape as the Lead and Customer APIs. field names the Shopify property at fault and is left out when the problem is the whole body. When a call is rejected, nothing from it is stored.

400 Bad Request
{
  "success": false,
  "errorCode": "INVALID_NUMBER",
  "message": "price must be a number, but \"₹1,250\" was sent.",
  "field": "price",
  "httpStatus": 400
}

INVALID_TYPE400An object or array was sent for a text property, variants is not an array, or an entry of it is not an objecttype must be text, but an object or array was sent.
INVALID_NUMBER400A number property carries something that is not a numberprice must be a number, but "₹1,250" was sent.
INVALID_BOOLEAN400A true/false property carries something other than true / falseavailable must be true or false, but "yes" was sent.
INVALID_DATE400created_at, published_at or a variant’s next_incoming_date is not a timestamp with a time zonecreated_at must be a timestamp with a time zone, such as 2026-11-17T10:30:00+05:30, but "2026-10-05 11:20:45" was sent.

401 is different. An expired or missing token is rejected by Salesforce before the endpoint runs, so the body is Salesforce’s own: [{"message": "Session expired or invalid", "errorCode": "INVALID_SESSION_ID"}].

08Testing in Postman

Import ShreeHari_Product_API.postman_collection.json. It holds the token call, the three sample requests from section 06, and one request that shows a 400 error.

  1. Open the collection’s Variables tab and fill in client_id and client_secret — the same Consumer Key and Secret as for the Lead API. instance_url is already set to UAT.
  2. Send 1. Get Access Token. It saves access_token into the collection automatically.
  3. Send 2. Send Product — suggested form. A 201 with a stagingProductNumber means the product is in Salesforce.
  4. Try the other requests. 5. Error — missing id should come back 400 MISSING_REQUIRED_FIELD with nothing stored.

To test your own data, paste a Shopify product JSON into the body of request 2. The sample files can also be sent as they are.
