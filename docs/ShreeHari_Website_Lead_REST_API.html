01Overview

02Authentication

The website uses the OAuth 2.0 Client Credentials flow to obtain a Bearer token before calling the endpoint. There is no user login and no redirect — two credentials are exchanged for a token directly, which is why this flow suits a server-to-server website integration.

Token request
POST https://agility-efficiency-7306--uat.sandbox.my.salesforce.com/services/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id={{CONSUMER_KEY}}
&client_secret={{CONSUMER_SECRET}}
Token response — 200 OK
{
  "access_token" : "00Dh20000003aVB!AQEAQI...",
  "instance_url" : "https://agility-efficiency-7306--uat.sandbox.my.salesforce.com",
  "token_type"   : "Bearer",
  "issued_at"    : "1758175020000",
  "api_instance_url" : "https://api.salesforce.com"
}

Get the Consumer Key and Consumer Secret from Setup → External Client App Manager → Shree Hari Website API → Settings → OAuth Settings → Consumer Key and Secret. They are issued once per environment and must be stored as secrets on the website server.

SettingValue in UAT
FlowClient Credentials — enabled
OAuth scopesapi, refresh_token, offline_access
Token lifetimePer session settings; re-authenticate on 401
IP relaxationEnforce IP restrictions

Two things that will block the first call.

  • IP restrictions are enforced on this app. The calling server's public IP — and the IP of the machine running Postman — must fall inside the Login IP Ranges of the integration user's profile. Otherwise the token call returns invalid_grant. Send us the website server's outbound IP and we will allowlist it.
  • Every call needs the header Authorization: Bearer {{access_token}}. A missing or expired token returns 401 with Salesforce's own body, not the error format in section 06.

04Create Lead

POST /services/apexrest/shreehari/v1/leads Create Lead

Creates one Salesforce Lead from a website or digital-channel enquiry and returns the new record Id.

Business rule: every enquiry lands as a Lead with Status = New and is routed by the active Lead assignment rule — to the tele-calling queue for online enquiries, or to the store queue when a storeCode is supplied. The tele-calling agent then qualifies the Lead, fills in Qualification Notes and Business Type, and converts it.

Fields deliberately not in this payload: Lead Owner, Mobile Phone and Campaign Id (standard). The handler sets Status = New, applies Business_Type__c and resolves Store_Association__c from the store code, then inserts with assignment rules switched on so the Lead reaches the right queue immediately. Everything after that — qualification, notes, conversion to Account and Contact — happens inside Salesforce and needs nothing further from the website.

08Testing in Postman

  1. Create an environment with four variables: instance_url, client_id, client_secret and access_token.
  2. Add a POST request to {{instance_url}}/services/oauth2/token. Body type x-www-form-urlencoded, with keys grant_type = client_credentials, client_id and client_secret. Send no Authorization header on this call.
  3. In that request's Scripts → Post-response tab, store the token so the next call picks it up automatically:
    Post-response script
    pm.environment.set("access_token", pm.response.json().access_token);
  4. Add a second POST request to {{instance_url}}/services/apexrest/shreehari/v1/leads with headers Authorization: Bearer {{access_token}} and Content-Type: application/json, and paste either sample body from section 04.
  5. Send. A 201 with a leadId means the Lead is in Salesforce — open it at {{instance_url}}/lightning/r/Lead/<leadId>/view to confirm the field mapping.

For UAT testing today: the only Store Location loaded in the sandbox is test store, store code 000001 — that is the value used in the B2C sample. Any other code will come back as STORE_NOT_FOUND until the real store list is loaded.

09Open points for review

Each of these needs a decision before the endpoint is built. They are listed in the order they affect the website team.

#PointImpact & recommendation
1 Endpoint not yet deployed The token call in section 02 works against UAT today. The /leads resource goes live once the Apex REST handler is deployed to the sandbox. Everything else in this document is already in place.
2 No idempotency key Lead carries no External Id field today, so a retried or double-submitted POST creates a second Lead. Recommended: add Website_Lead_ID__c (Text 64, External Id, Unique) and switch this endpoint to an upsert on it. The website would then send its own enquiry reference and retries would become safe.
3 Mobile Phone not available Lead in this org exposes Phone but not MobilePhone, Fax or DoNotCall. The mobile number goes in phone. Confirm whether a separate Mobile Phone field is wanted before build.
4 Store list Store Location currently holds one test record. Store codes must be loaded and shared with the website team so the store dropdown matches Salesforce exactly.
5 Assignment rule The routing in section 07 assumes an active Lead assignment rule covering the tele-calling queue and the store queues. Confirm the rule and queue names.
6 IP allowlisting The External Client App enforces IP restrictions. Share the website server's outbound IP — and the testers' IPs — so they can be added to the integration user's profile.
7 Which source value Confirm which leadSource the website should send. Shopify is assumed in the samples; the value drives channel reporting, so it should be agreed before go-live.
