Integration Specification

Shopify → Salesforce Customer REST API

How the Shree Hari website sends Shopify customer records into Salesforce. Uses the same External Client App and the same access token as the Lead API; only the URL and the payload differ. Prepared by Halsa Global for the Shree Hari Jewellers website team.

ProtocolREST / JSON
AuthSame as Lead API · OAuth 2.0
PayloadShopify customer object
EnvironmentUAT Sandbox

01Overview

Integration pattern: the website POSTs one Shopify customer as JSON, in the shape of the Shopify Liquid customer object. Salesforce stores it as one Staging Customer record and returns that record’s Id and number. Property names are the Shopify names, unchanged.

Every call creates a new Staging Customer record, so Salesforce keeps a full history of what was sent. Records are processed inside Salesforce afterwards and need nothing further from the website.

02Authentication

Exactly as for the Lead API: the OAuth 2.0 Client Credentials flow with the same Consumer Key and Consumer Secret. One token works for both endpoints, so a website already calling the Lead API needs no new credentials — only the new URL.

Token request
POST https://agility-efficiency-7306--uat.sandbox.my.salesforce.com/services/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id={3MVG9Nm09gOGRa5Cfj84CC2IPJsONJWs_OXZeRMB6R.}
&client_secret={FFFF54A591E99C14256954FA717A}

Use the access_token from the response in the header Authorization: Bearer {{access_token}}. The IP restrictions described in the Lead API document apply here too: calls must come from an allowlisted IP address.

03Conventions

ConventionDetail
Content-Typeapplication/json
Character setUTF-8
Property namesExactly the Shopify Liquid customer property names, in snake_case — first_name, orders_count, b2b?. Names ending in ? are also accepted without it (b2b, has_avatar)
Payload shapeOne customer per request, as one JSON object with the properties at the top level, exactly as in the samples in section 04. Arrays of customers are rejected
RequiredOnly id. Send every other property you have
Empty valuesnull is accepted and leaves the field blank. An empty string "" for a number or true/false property also counts as no value
NumbersJSON numbers, unformatted — 18750000. Numeric text such as "18750000" is also accepted; "1,87,500" is rejected
Moneytotal_spent is in the currency’s subunit, as Shopify Liquid outputs it (paise for INR) and is stored as sent
BooleansJSON true / false. The text "true" / "false" is also accepted (any letter case); anything else, such as "yes" or 1, is rejected
Objects and arraysSend them as Shopify produces them (addresses, orders, metafields …). They are stored as JSON text, unchanged
Other propertiesAny property not listed in section 04 is not rejected: it is kept on the record in Additional Properties, so nothing sent is lost
Fixed value listsNone. The Shopify customer object defines no property with a fixed set of values
Repeats and retriesEach successful call creates a new record, including a retry of a call that already succeeded. Retry only on 401 (after re-authenticating) and 500

Sample response

201 Created
{
  "success": true,
  "stagingCustomerId": "a0Rh2000000AbCdEAK",
  "stagingCustomerNumber": "SC-12",
  "shopifyCustomerId": "7364019208385",
  "message": "Customer received and stored as SC-12."
}

stagingCustomerId and stagingCustomerNumber identify the Salesforce record; keep them in your logs. shopifyCustomerId echoes the id you sent, as text.

HTTP status codes

StatusMeaning
201 CreatedCustomer stored — stagingCustomerId returned
400 Bad RequestMalformed JSON, missing id, a value of the wrong type, or a value too long. Nothing is stored; fix the payload and send again
401 UnauthorizedMissing or expired Bearer token — re-authenticate and retry once
500 Server ErrorSalesforce could not save the record — safe to retry

05Error responses

Every error raised by the endpoint uses the same JSON shape as the Lead API. field names the Shopify property at fault and is left out when the problem is the whole body. When a call is rejected, nothing from it is stored.

400 Bad Request
{
  "success": false,
  "errorCode": "INVALID_NUMBER",
  "message": "orders_count must be a number, but \"three\" was sent.",
  "field": "orders_count",
  "httpStatus": 400
}
Error codeHTTPWhen it occursExample message
INVALID_JSON400The body is empty, is not valid JSON, or is not one JSON object (for example an array of customers)Request body must be one customer as a JSON object (one customer per call).
MISSING_REQUIRED_FIELD400id is missing, null or blankid is required: the Shopify customer ID.
INVALID_TYPE400An object or array was sent for a text property (id, name, first_name, last_name, email, phone)email must be text, but an object or array was sent.
INVALID_NUMBER400A number property carries something that is not a numberorders_count must be a number, but "three" was sent.
INVALID_BOOLEAN400A true/false property carries something other than true / falseaccepts_marketing must be true or false, but "yes" was sent.
VALUE_TOO_LONG400A value is longer than its field in section 04, or a number is too largefirst_name is 256 characters long; at most 255 can be stored.
DML_EXCEPTION500Salesforce could not save the recordThe Salesforce error text

401 is different. An expired or missing token is rejected by Salesforce before the endpoint runs, so the body is Salesforce’s own: [{"message": "Session expired or invalid", "errorCode": "INVALID_SESSION_ID"}].

06Testing in Postman

Import ShreeHari_Customer_API.postman_collection.json. It holds the token call, the two sample requests from section 04, and one request that shows a 400 error.

  1. Open the collection’s Variables tab and fill in client_id and client_secret — the same Consumer Key and Secret as for the Lead API. instance_url is already set to UAT.
  2. Send 1. Get Access Token. It saves access_token into the collection automatically.
  3. Send 2. Send Customer — full. A 201 with a stagingCustomerNumber means the customer is in Salesforce.
  4. Try the other requests. 4. Error — missing id should come back 400 MISSING_REQUIRED_FIELD with nothing stored.

To test your own data, paste a Shopify customer JSON into the body of request 2. The sample files can also be sent as they are.
