Integration Specification

Abandoned Checkout and Cart → Salesforce REST API

How the Shree Hari website team sends Magic Checkout checkout.abandoned and cart.abandoned events into Salesforce. Uses the same External Client App and access token as the Lead, Customer, Product and Order APIs. Prepared by Halsa Global for the Shree Hari Jewellers website team.

ProtocolREST / JSON
AuthSame as Lead API · OAuth 2.0
PayloadMagic Checkout v2.0 event
EnvironmentUAT Sandbox

01Overview

Integration pattern: send one event per request, as one JSON object, without changing its keys. Both event types go to the same URL. Salesforce creates a Lead for a new person or an enquiry Case for an existing customer, and tells you which in the response.

Razorpay cannot post to this URL directly. Salesforce requires an OAuth Bearer token, which a Razorpay webhook does not send. Your server must receive the webhook, verify X-Razorpay-Signature, and forward the unchanged JSON to Salesforce with a token.

03Conventions

ConventionDetail
Content-Typeapplication/json
Payload shapeOne event per request, with event and data at the top level. The legacy "event": "abandoned_checkout" format is rejected
Accepted eventscheckout.abandoned and cart.abandoned only. Do not forward other events, such as cart.session_abandoned; they return 400
Key namesExactly as in the event, and case-sensitive
Other keysAccepted and ignored. They are not stored, so new Razorpay fields will not break the call
PhoneIndian number: 10 digits, optionally starting with +91 or 91. Spaces and dashes are allowed. Numbers from other countries are rejected
ConsentJSON true ticks the box. Anything else, including the text "true", leaves it unticked
RepeatsSalesforce does not store event.id. Please deduplicate on it before forwarding: a repeated event for an existing customer raises another Case
RetriesRetry only on 401 (after getting a new token) and 500. Do not retry 400 or 409; the same request will fail again

05What Salesforce does with each event

The phone and email are compared with existing Accounts, Contacts and open Leads, in this order:

#Found in SalesforceResultResponse
1Account with a matching ContactEnquiry Case on both201 ENQUIRY_CREATED
2Account onlyNew Contact under the Account, then Case on both201 ENQUIRY_CREATED, contactCreated: true
3Contact onlyNew Account, Contact moved under it, then Case on both201 ENQUIRY_CREATED, accountCreated: true
4Open LeadNothing is created or updated200 DUPLICATE_LEAD
5No matchNew Lead201 CREATED

VALUE_TOO_LONG400A value is longer than its fielddata.user.user_id is 256 characters. The maximum is 255.
INVALID_ADDRESS400State or country is not a recognised name. field shows state for bothThe address was rejected by Salesforce: There's a problem with this state…
DUPLICATE_DETECTED409A Salesforce duplicate rule refused the recordA Salesforce duplicate rule blocked this record: Use one of these records?
DML_EXCEPTION500Salesforce could not save the recordThe Salesforce error text

401 is different. Salesforce rejects an expired or missing token before the endpoint runs, so the body is [{"message": "Session expired or invalid", "errorCode": "INVALID_SESSION_ID"}].

08Testing in Postman

Import ShreeHari_Abandoned_Checkout_API.postman_collection.json.

  1. Open the collection’s Variables tab and fill in client_id and client_secret. instance_url is already set to UAT.
  2. Send 1. Get Access Token. It saves access_token automatically.
  3. Send 2. Checkout Abandoned or 3. Cart Abandoned. A 201 means Salesforce created a Lead or Case.
  4. Send the same request again. It returns 200 DUPLICATE_LEAD if the first call created a Lead.
  5. 5. Error — missing contact should return 400 MISSING_REQUIRED_FIELD with nothing created.
