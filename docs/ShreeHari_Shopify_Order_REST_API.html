Integration Specification

Shopify → Salesforce Order REST API

How the Shree Hari website sends Shopify order records into Salesforce. Uses the same External Client App and the same access token as the Lead, Customer and Product APIs; only the URL and the payload differ. Prepared by Halsa Global for the Shree Hari Jewellers website team.

ProtocolREST / JSON
AuthSame as Lead API · OAuth 2.0
PayloadShopify order object
EnvironmentUAT Sandbox

01Overview

Integration pattern: the website POSTs one Shopify order as JSON, in the shape of the Shopify Liquid order object. Salesforce stores it as one Staging Order record and returns that record’s Id and number. Property names are the Shopify names, unchanged.

SourceShopify
order

TransportHTTPS POST
Bearer token

SalesforceApex REST
/shreehari/v1/orders

ResultStaging Order
SO-number

Every call creates a new Staging Order record, so Salesforce keeps a full history of what was sent. When an order changes (paid, fulfilled, refunded, cancelled), send the whole order again: it is stored as a further record with the same id. Records are processed inside Salesforce afterwards and need nothing further from the website.

Whatever you send is stored. All 44 properties of the Shopify order object have a field, and any other key is kept in Additional Properties.

02Authentication

Exactly as for the Lead API: the OAuth 2.0 Client Credentials flow with the same Consumer Key and Consumer Secret. One token works for the Lead, Customer, Product and Order endpoints, so a website already calling the Lead API needs no new credentials — only the new URL.

03Conventions

ConventionDetail
Content-Typeapplication/json
Character setUTF-8
Property namesExactly the Shopify Liquid order property names, in snake_case — financial_status, total_price, pickup_in_store?. The name ending in ? is also accepted without it (pickup_in_store). Names are case-sensitive: Email is not email and would be kept in Additional Properties
Payload shapeOne order per request, as one JSON object with the properties at the top level, exactly as in the samples in section 06. A body of the form {"order": {…}} is also accepted. Arrays of orders are rejected
RequiredOnly id
Empty valuesnull is accepted and leaves the field blank. A property that is left out also leaves its field blank. An empty string "" for a number, true/false, timestamp or fixed-list property is treated as no value
NumbersJSON numbers, unformatted — 11587500. Numeric text such as "11587500" is also accepted; "1,15,875" and "₹1,15,875" are rejected
MoneyThe nine amount properties are in the currency’s subunit, as Shopify Liquid outputs them (paise for INR), and are stored as sent. Amounts inside line_items, transactions and the other objects are stored as sent too
BooleansJSON true / false. The text "true" / "false" is also accepted (any letter case); anything else, such as "yes" or 1, is rejected. A true/false property that is left out is stored as false
Timestampscreated_at and cancelled_at must carry a time zone. Accepted: "2026-11-01 10:30:00 +0530" (as Shopify Liquid outputs it), "2026-11-01T10:30:00+05:30", "2026-11-01T05:00:00Z". A value without a time zone is rejected. Timestamps inside objects (a transaction’s created_at) are not checked
Fixed value listsfinancial_status and cancel_reason accept only the values Shopify documents, in lower case, exactly as listed in section 04. fulfillment_status_label accepts any text
Objects and arraysStored as JSON text, unchanged, whatever their content
Other propertiesAny property not listed in section 04 is not rejected: it is kept on the record in Additional Properties (up to 131,072 characters of JSON for all such properties together), so nothing sent is lost
Repeats and retriesEach successful call creates a new record, including a retry of a call that already succeeded. Retry only on 401 (after re-authenticating) and 500

05The 18 large properties — what to send

Eighteen of the 44 properties hold an object, a list or long text. The table says what to send for each one.

  • ALL — send the property complete, exactly as Shopify gives it.
  • ID / NAME ONLY — send only the ID or the name.
  • LEAVE OUT — do not send the property.

This is based on our standing of the Shopify documentation. Nothing here is enforced: whatever you send is stored as sent. If a property we mark ID / NAME ONLY or LEAVE OUT holds information you need kept, send it complete.

#PropertyLabelWhat to sendReason
1line_itemsALLEvery line item, complete.What was bought.
2billing_addressALLThe complete address.Where the order was billed.
3shipping_addressALLThe complete address, even when it is the same as billing. null if there is none.Where the order was shipped.
4transactionsALLEvery transaction, complete. Do not include a gift card’s code.Payments and refunds of the order. A gift card code can be used to spend the card.
5shipping_methodsALLEvery shipping method, complete.How the order was shipped and at what price.
6tax_linesALLEvery tax line, complete.Tax charged on the order.
7discount_applicationsALLThe complete array.Every discount on the order.
8cart_level_discount_applicationsALLThe complete array.Which discounts apply to the whole order.
9metafieldsALLEvery order metafield: namespace, key, type and value.Extra order details your store keeps.
10attributesALLThe complete object.Names and values entered with the cart.
11tagsALLThe complete array.Tags on the order.
12noteALLThe complete text.The customer’s note.
13customer_order_urlALLThe URL as text.Link to the order.
14customer_urlALLThe URL as text.Link to the order.
15order_status_urlALLThe URL as text.Link to the order status page.
16customerALLid, first_name, last_name, email, phone.The complete customer is sent through the Customer API.
17subtotal_line_itemsALLsend if any.Same items as line_items, unless the order has a tip.
18discountsALLsend if any.Deprecated by Shopify; replaced by discount_applications.

Size limit. Each property can hold the length shown in section 04; a longer value is rejected with VALUE_TOO_LONG and the order is not stored.

07Error responses

08Testing in Postman

Import ShreeHari_Order_API.postman_collection.json. It holds the token call, the three sample requests from section 06, and one request that shows a 400 error.

  1. Open the collection’s Variables tab and fill in client_id and client_secret — the same Consumer Key and Secret as for the Lead API. instance_url is already set to UAT.
  2. Send 1. Get Access Token. It saves access_token into the collection automatically.
  3. Send 2. Send Order — suggested form. A 201 with a stagingOrderNumber means the order is in Salesforce.
  4. Try the other requests. 5. Error — missing id should come back 400 MISSING_REQUIRED_FIELD with nothing stored.

To test your own data, paste a Shopify order JSON into the body of request 2. The sample files can also be sent as they are.
